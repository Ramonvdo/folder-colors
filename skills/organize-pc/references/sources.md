# Sources

What the presets and the doctrine were built from, with the date read. Re-research map:
question a rule, start at its source.

- **Alex Hormozi**, as relayed in a Gemini thread the repo owner supplied (2026-09-11):
  numbered value-chain areas, depth of three, `YYYY-MM-DD_Type_Name` names, Downloads as a
  transit hub with automatic deletion, zero desktop icons, a templates folder, a
  `00_README` SOP pinned at the top of every folder, local for heavy working files and
  cloud for deliverables, weekly audit. Not a primary source; the preset B outline and
  the transit-folder rules come from it, marked as such.
- **Tiago Forte, "The PARA Method"**, fortelabs.com/blog/para (2023, updated 2026-04-15).
  Read 2026-09-12. Contributed preset C: Projects ("short-term efforts ... with a certain
  goal"), Areas ("important parts of your work and life that require ongoing attention"),
  Resources (topics you are interested in), Archives (anything no longer active but worth
  keeping); the decision rule "organize by actionability"; movement between the four
  over time. No numbering or naming guidance in the article.
- **Johnny.Decimal, "11.01 Introduction"**, johnnydecimal.com/10-19-concepts/11-core/
  11.01-introduction. Read 2026-09-12. Contributed the numbering option: areas 10-19,
  20-29 ...; categories 11-19 inside an area; IDs `11.01`; the "no more than 10" limit at
  every level; numbers keep folders from reordering when new ones appear ("If you use the
  alphabet to name folders, they move when a new one is created"); "The ID tells us
  exactly where a thing is". The paid "15.04 Small Business System" outline was not read.
- **brayansdt/organize-folder-skill** (`SKILL.md`, read 2026-09-11): the five-phase
  shape, "never move anything before approval", the overlap check, `misc/` as an honest
  holding pen, the reference-versus-recurring split, a README written for the exact
  structure created.
- **llm-wiki** and **obsidian-markdown** skills on this machine (read 2026-09-11): an
  index kept current, an append-only log, a schema written for the specific instance,
  "ask first, briefly", frontmatter and links so documents can live in a vault.
